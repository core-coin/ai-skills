# Ecosystem overview

The [index](index.md) routes by practical task. The ecosystem includes a client and consensus layer, mining implementations, cryptographic and encoding libraries, CVM and contract tooling, wallets and language SDKs, APIs and indexing, and deployment and packaging repositories. These are categories for navigation, not claims that all projects interoperate or are actively maintained.

`go-core` is the client reference for compatibility work. `RandomY`, `go-randomy`, and `randomy-rs` have distinct source identities and languages. `cvm` and `yvm-rs` are separate projects; inspect both before assuming equivalent interfaces. `go-goldilocks` and `libgoldilocks` are distinct repositories. `luna-sdk` and `luna_sdk`, and `compact-money` and `compact_money`, must likewise be selected by their actual README and package interface rather than their similar names.

Cryptographic, encoding, and ABI libraries can support clients, wallets, SDKs, and contract tools, but a sibling checkout does not automatically replace a published package dependency. Check manifests and lockfiles before claiming a direct dependency. Payment formats, transaction transport, and infrastructure tools occupy different layers from consensus. A repository's presence in this catalog does not imply production readiness, current maintenance, or deployment use.

The [CIP registry](repositories/core-coin/cip.md) documents standards and proposals. Its compact `llms.txt` index points to individual final proposals; proposal status alone does not prove network activation. [`ylem-splitting`](repositories/core-laboratories/ylem-splitting.md) is a specific fee-splitting contract, while [`remix`](repositories/core-laboratories/remix.md) remains uninspected because repository access failed. The supplied [Contract Deployer README](contract-deployer.md) describes a local GUI but did not identify a repository URL. The user-provided [IPFS Worker](repositories/core-laboratories/ipfs-worker.md) and [ORIC](repositories/core-laboratories/oric.md) READMEs describe infrastructure and API services; their source is still unavailable.

For offline transfer of already-signed transactions, [`flutter_barcodetx`](repositories/DataLayerHost/flutter_barcodetx.md) encodes animated QR frames and [`ScanBarcode`](repositories/DataLayerHost/ScanBarcode.md) can reconstruct them on a desktop receiver. ScanBarcode displays transaction hex; signing and broadcast belong to separate applications. Its deeplink actions and optional update checks can involve the OS or network, so inspect those paths when designing an air-gapped workflow.

See [protocol and compatibility](protocol-and-compatibility.md) for the owner's modernization goals, which are separate from verified repository behavior. Each repository page identifies the source revision behind its facts.
